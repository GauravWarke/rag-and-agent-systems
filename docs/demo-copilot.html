Support Knowledge Copilot

Ask a question about the sample product documentation. The system retrieves candidate passages, verifies that every citation actually supports the answer, and scores its own confidence — or tells you the answer isn't in the docs.

How this demo works: the retrieval pipeline — BM25, hashed embeddings, Reciprocal Rank Fusion, citation verification, confidence scoring — is ported from the Python service to JavaScript so it runs entirely in your browser. No server, no API key, no network calls. Same algorithm and parameters as the repo; answer generation is extractive in both.
Retrieval strategy

What happens when you press Ask

  1. Chunking. The corpus is split on headings into 26 passages. The heading is indexed with the body — a section called "Refund window" should match the word window even when the prose never uses it.
  2. Normalisation. Tokens are stopword-filtered and suffix-stemmed, so refund, refunds and refunded collapse to one term. The stemmer is deliberately conservative: aggressive rules collapse apply into app, which makes unrelated passages look relevant.
  3. Sparse retrieval. BM25 (k₁ = 1.5, b = 0.75) on term overlap. Strong on exact matches — product names, error codes, specific numbers.
  4. Dense retrieval. A deterministic stub embedder hashes tokens and character trigrams into a 256-dimension signed vector, compared by cosine. A stand-in for a real embedding model with an identical interface, so swapping one in changes one function.
  5. Fusion. Reciprocal Rank Fusion — Σ 1/(60 + rank) — needs no score calibration between two very differently-scaled methods.
  6. Grounding check. If the top passage doesn't contain at least a third of the query's content terms, the system declines. This gate exists because the failure that matters isn't a missing answer, it's a confident wrong one.
  7. Answer + verification. Sentences are scored by IDF-weighted overlap and weighted by their parent passage's rank, so a weak sentence from an unrelated passage can't outrank a strong one from the best passage. Each citation is then re-checked against its source; one that doesn't carry the answer's content is flagged, not hidden.
  8. Confidence. 0.5 × retrieval strength + 0.3 × citation support + 0.2 × query coverage.

Known limitation. Selection is extractive and lexical — it has no model of what "how long" means. Ask "how long is the free trial" and it returns true sentences about the trial without necessarily leading with "14 days". Fixing that needs either question-type classification or an abstractive generation step; both are noted in the repo's roadmap rather than papered over here.
