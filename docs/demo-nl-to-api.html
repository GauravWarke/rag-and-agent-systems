Natural Language to API Assistant

Type a request against the sample OpenAPI schema below. The planner resolves which endpoints are needed and in what order, validates every parameter against the spec, and dry-runs anything that writes before it commits.

Where the LLM sits: exactly one stage — turning your sentence into a structured intent. In this demo that stage is pattern-matched so the page runs offline; it's drawn with a dashed border below. Every stage after it — endpoint selection, dependency planning, schema validation, write classification, dry-run — is deterministic and is the same logic as the repo. That boundary is the design: the model proposes, the schema disposes.

The pipeline, stage by stage

  1. Intent. The one model-dependent step: free text becomes a structured intent plus extracted entities. Isolating it to a single stage means everything downstream is testable without a model in the loop — which is why the test suite runs offline.
  2. Endpoint selection. The intent is matched against operations in the schema. No match means a clean refusal; the planner never fabricates a path.
  3. Dependency planning. Most useful requests need several calls where later ones depend on earlier results. The planner emits an ordered plan with explicit references — $1.id means "the id from step 1" — so the data flow is inspectable before anything runs.
  4. Validation. Every parameter is checked against the spec: type, required, enum membership, numeric bounds. A plan that wouldn't survive the API is caught here rather than producing a 400 halfway through a sequence.
  5. Write classification. Operations are split by whether they mutate. Reads proceed; writes are held.
  6. Dry-run. Writes are simulated against current state and the result shown as a diff. You see what would change before agreeing to change it.
  7. Confirm. Nothing that writes executes without an explicit yes. The confirmation shows the concrete diff, not a restatement of the original request.
