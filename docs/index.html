01Retrieval

Support Knowledge Copilot

Answers questions from internal documentation and shows exactly which passage supports each claim — so the answer can be checked rather than trusted blindly.

  • Hybrid retrieval: dense embeddings and BM25, fused with Reciprocal Rank Fusion
  • Every citation verified against the source text before it's returned
  • Confidence scored from retrieval strength, citation support and completeness
  • Returns "I could not find this in the docs" instead of guessing

02Data quality

RAG Freshness & Drift Monitor

A knowledge base decays quietly. This watches for documents going stale and embeddings drifting from the corpus, so the problem surfaces before a user hits a wrong answer.

  • Tracks age, revision cadence and last-verified date per document
  • Flags index drift when embeddings diverge from the current corpus
  • Ranks by blast radius — how often a stale document is actually retrieved
  • Emits alerts a scheduled job can act on

03Agents

Permissioned Agent Sandbox

Giving an agent tools is the easy part. This is about what happens when it reaches for one it shouldn't — every tool carries permissions, limits and an audit trail.

  • Per-tool permission scopes checked before execution, not after
  • Rate limits and budget ceilings enforced at the tool boundary
  • Consequential actions pause and wait for explicit human approval
  • Full audit log of every call, argument and decision

04Tool calling

Natural Language to API Assistant

Reads an OpenAPI schema, works out which calls a request needs and in what order, validates the parameters, and dry-runs anything that writes before committing.

  • Plans multi-step call sequences from the schema, not from guesswork
  • Parameters validated against the spec before a request is sent
  • Writes are simulated first and shown for confirmation
  • Refuses cleanly when the schema can't satisfy the request

05Multimodal

Multimodal Document Reviewer

OCR handles the clean pages cheaply. A vision model takes over where confidence drops. Anything still uncertain goes to a person rather than silently downstream.

  • Cost-aware cascade — vision only runs where OCR is weak
  • Per-field confidence, not one score for the whole document
  • Low-confidence fields routed to a human review queue
  • Structured output validated against the expected schema

Built to be verified.

Four constraints every one of these systems was held to.

01

Cite or decline

An answer without a verifiable source isn't returned. Saying "not in the docs" is a valid outcome.

02

Gate the risky path

Anything consequential stops for a human. Permissions are checked before execution, not audited after.

03

Independent verification

Ruff and pytest run separately from the agent that wrote the code. A failing check blocks the merge.

04

Reproducible offline

Deterministic stub embeddings mean the suite runs with no API key and no network. Same input, same result.

Approach

How these were built

Worth being direct about, because the process is part of what the projects demonstrate.

I wrote the architecture and acceptance criteria for each system, then had a scheduled GitHub Actions pipeline implement against that roadmap. Nothing merges on the agent's say-so — an independent CI gate runs the linter and the test suite, and a failing check blocks the pull request regardless of what the agent reported. Designing that verification loop was most of the engineering, and it's the part I'd point at first if you're learning this.

Run it
