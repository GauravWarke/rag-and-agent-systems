01Answering questions

Support Knowledge Copilot

Ask a question about a company's help documents. It answers, and shows the exact passage each part of the answer came from, so you can check it yourself.

  • Finds the passages that relate to your question, then writes the answer only from them. This approach is called retrieval-augmented generation (RAG).
  • Searches two ways at once, by meaning and by exact words, and merges the two result lists. That is hybrid retrieval.
  • Checks that every quoted source really says what the answer claims: citation verification.
  • Says “I couldn't find this” instead of guessing, and rates how sure it is from 0 to 1. That rating is a confidence score.
Go deeper
Dense embeddings (search by meaning)
Each passage becomes a list of numbers, a kind of fingerprint of its meaning. Passages with similar meaning get similar numbers, even if they share no words.
BM25 (search by exact words)
A classic scoring formula that rewards passages sharing rare words with your question. Also called sparse retrieval.
Reciprocal Rank Fusion (RRF)
The rule used to merge the two ranked lists: a passage scores well if it ranks high in either.

02Keeping answers up to date

RAG Freshness & Drift Monitor

Documents go out of date, and an AI that reads them starts giving old answers. This tool spots outdated documents before anyone gets a wrong answer.

  • Flags documents nobody has checked in a long time. These are called stale documents.
  • Remember the search by meaning from project 01? Its number fingerprints (embeddings) were made from the old text. When the text changes but the fingerprints don't, that gap is index drift.
  • Fixes the most-used documents first, ranked by blast radius: how many answers each stale document could spoil.
Go deeper
Re-embedding and rebuild cadence
Fixing drift means recomputing the fingerprints (re-embedding). You can do it on a timer (the cadence, e.g. nightly) or only for documents that changed.
Detector recall
The share of real changes a change detector actually notices. It decides whether watching for changes beats a simple timer; the demo lets you test this.

03Safe AI assistants

Permissioned Agent Sandbox

An AI assistant that can take actions, like searching files or sending an email, but only the ones it is allowed to. Risky actions wait for a person to approve them.

  • An AI that chooses actions to finish a task is called an agent. Each action it can take, like “send email”, is a tool.
  • Before any tool runs, it checks the user's role is allowed to use it. That allowed list is a permission scope.
  • Risky tools pause until a person approves. Keeping a person in charge of key decisions is called human-in-the-loop (HITL).
  • Every action and decision is written to an audit log.
Go deeper
Rate limit
A cap on how many tool calls are allowed per minute, so a looping agent can't overload anything.
Risk tier and budget ceiling
Each tool is labelled low to critical risk, and tools that spend money draw from a fixed budget.
Hash-chained log
Each log entry is linked to the one before, so deleting or editing any entry is detectable.

04Plain English to actions

Natural Language to API Assistant

Type a request like “move the Acme order to express shipping.” It works out the steps, checks them, and shows you a preview before changing anything.

  • Software systems talk to each other through an API. Here, every step the assistant takes is one API call to a sample business app.
  • The API comes with an OpenAPI schema: a machine-readable list of every action it supports. The assistant plans only from that list, and says no if your request isn't in it.
  • Like the agent in project 03, it chooses tools. Picking a function and filling in its inputs, instead of writing free text, is called tool calling.
  • Changes are simulated first and shown to you as a preview: a dry run.
Go deeper
Intent extraction
The only step that needs an AI model: turning your sentence into a structured request.
Dependency planning
Ordering calls so later steps use earlier results (find the customer, then their order).
Parameter validation
Checking every input's type, required fields and allowed values against the schema before sending.

05Reading documents

Multimodal Document Reviewer

Upload a scanned form or invoice. It pulls out the key details, like names, dates and totals, and sends anything it isn't sure about to a person to check.

  • Clean pages are read with OCR (optical character recognition), which turns a picture of text into text. Fast and cheap.
  • Hard pages go to a vision model, an AI that reads images directly. Working with both text and images is what multimodal means.
  • Trying the cheap method first and moving up only when needed is called a cascade.
  • Each field gets its own confidence score (project 01). Low scores go to a person: the human-in-the-loop idea from project 03.
Go deeper
Thresholds
The confidence cut-offs that decide when to move up the cascade. The demo lets you drag them.
Expected error
A field that is 90% certain counts as 0.1 of a mistake. Adding these up estimates errors per document.
Cost-aware routing
Choosing the method per field by weighing processing cost against the cost of a mistake.

Built to be checked.

Four rules every project follows.

01

Show a source, or say no

No answer goes out without a source you can check. “I don't know” is an allowed answer.

02

Ask before risky actions

Anything that could cause harm waits for a person. Permission is checked before acting, not after.

03

Checked by something else

Automated tests run separately from the AI that wrote the code. If they fail, the change can't go in.

04

Works offline

No API key or internet needed. The same input always gives the same result.

How it's built

How these were built

The process is part of what these projects show.

I designed each system and wrote down what “done” means for it. An AI coding agent then wrote the code, on a schedule. Before any change is accepted, a separate set of automated checks runs on it: a style checker (Ruff) and the test suite (pytest). Engineers call this continuous integration, or CI. If a check fails, the change is blocked, whatever the agent reported. Building that checking step was most of the work.

Run it yourself

Two minutes, no keys

The demos above run in your browser. To run the real software on your own computer, you need Python. Paste these four lines into a terminal, then open the link on the last line. It opens an interactive page (/docs) where you can send the service questions.

cd rag-and-agent-systems/01-support-knowledge-copilot
