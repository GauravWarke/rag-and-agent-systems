01Answering questions

Support Knowledge Copilot

Ask it something about a company's help docs. You get an answer plus the exact passage behind each part of it, so you don't have to take it on trust.

  • First it pulls out the passages that relate to your question. Then it writes the answer using only those. People call this retrieval-augmented generation (RAG).
  • It searches twice: once for passages that mean the same thing, once for passages with the same words. Blending the two lists is hybrid retrieval.
  • Before replying, it rereads each quoted source to make sure it really says what the answer claims. That step is citation verification.
  • If the docs don't cover it, it says so rather than guessing. Every answer also carries a number from 0 to 1 for how sure it is: its confidence score.
Go deeper
Dense embeddings (search by meaning)
Each passage becomes a list of numbers, a kind of fingerprint of its meaning. Passages with similar meaning get similar numbers, even if they share no words.
BM25 (search by exact words)
A classic scoring formula that rewards passages sharing rare words with your question. Also called sparse retrieval.
Reciprocal Rank Fusion (RRF)
The rule used to merge the two ranked lists: a passage scores well if it ranks high in either.

02Keeping answers up to date

RAG Freshness & Drift Monitor

Docs age. When they do, an AI reading them quietly starts giving old answers. This tool catches outdated docs before a real person gets burned by one.

  • It flags docs nobody has looked at in ages. The usual word for these is stale.
  • Think back to search by meaning in project 01. It works from number fingerprints of each passage (embeddings), made from the text as it was then. Edit the text without redoing the fingerprints and the two start to disagree. That gap is index drift.
  • The docs people ask about most get fixed first. The ranking uses blast radius, meaning how many answers one stale doc could spoil.
Go deeper
Re-embedding and rebuild cadence
Fixing drift means recomputing the fingerprints (re-embedding). You can do it on a timer (the cadence, e.g. nightly) or only for documents that changed.
Detector recall
The share of real changes a change detector actually notices. It decides whether watching for changes beats a simple timer; the demo lets you test this.

03Safe AI assistants

Permissioned Agent Sandbox

This assistant can actually do things, like search files or send an email. It can only do what it's been allowed to, though, and anything risky waits until a person says yes.

  • When an AI picks its own actions to get a job done, it's called an agent. Every action on its menu, “send email” for example, is a tool.
  • No tool runs until the user's role is checked against the tools that role may use. That list is its permission scope.
  • Risky tools stop and wait for a human. Keeping a person responsible for the big calls is known as human-in-the-loop (HITL).
  • Everything it does, and every decision about it, lands in an audit log.
Go deeper
Rate limit
A cap on how many tool calls are allowed per minute, so a looping agent can't overload anything.
Risk tier and budget ceiling
Each tool is labelled low to critical risk, and tools that spend money draw from a fixed budget.
Hash-chained log
Each log entry is linked to the one before, so deleting or editing any entry is detectable.

04Plain English to actions

Natural Language to API Assistant

Type something like “move the Acme order to express shipping.” It figures out the steps, double-checks them, and shows you exactly what would change before touching anything.

  • Programs talk to each other through an API. Each step this assistant takes is one API call to a sample business app.
  • That API ships with an OpenAPI schema, basically a menu of every action it supports, written for machines. The assistant only plans from that menu. Ask for something that isn't on it and you get a no.
  • It picks tools the same way the agent in project 03 does. Choosing a function and filling in its inputs, rather than just writing text, is tool calling.
  • Anything that changes data gets rehearsed first and shown to you as a preview. That rehearsal is a dry run.

05Reading documents

Multimodal Document Reviewer

Give it a scanned form or invoice. It pulls out the details that matter (names, dates, totals) and hands anything it isn't sure of to a person.

  • Clean pages go through OCR (optical character recognition), which turns a photo of text into actual text. It's quick and cheap.
  • Messy pages get passed to a vision model, an AI that looks at the image itself. Handling text and images together is what multimodal means.
  • Start cheap, and only step up when you have to. That pattern is a cascade.
  • Every field gets its own confidence score, same idea as project 01. Low scores go to a person, which is the human-in-the-loop idea from project 03.
Go deeper
Thresholds
The confidence cut-offs that decide when to move up the cascade. The demo lets you drag them.
Expected error
A field that is 90% certain counts as 0.1 of a mistake. Adding these up estimates errors per document.
Cost-aware routing
Choosing the method per field by weighing processing cost against the cost of a mistake.

Built to be checked.

Four rules I held every project to.

01

Show a source, or say no

Nothing goes out without a source you can check for yourself. “I don't know” counts as a fine answer.

02

Ask before risky actions

If an action could do damage, a person signs off first. Permissions get checked up front, not after the fact.

03

Checked by something else

The tests run apart from the AI that wrote the code. A failing test blocks the change, full stop.

04

Works offline

No API key, no internet. Run it twice with the same input and you get the same result.

How it's built

How these were built

How they were made is part of the point.

I designed each system and spelled out what “done” meant for it. Then an AI coding agent wrote the code on a schedule. Every change had to get past a separate set of automated checks before it could go in: a style checker (Ruff) and the test suite (pytest). Engineers call this continuous integration, or CI. A failed check blocked the change no matter what the agent claimed. Getting that checking step right took most of the effort.
